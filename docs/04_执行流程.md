# Stage 3 框架执行流程

```text
run.py
  ├─ 解析 --env / --level / CLI API 覆盖
  ├─ core.ConfigManager
  │    └─ CLI > 环境变量 > env.<name>.yaml > config.yaml
  ├─ 创建 reports/runs/<run_id>/
  ├─ 写入 API_TEST_ENV / API_HOST / API_TIMEOUT / API_VERIFY_SSL / API_USE_MOCK
  └─ pytest.main
       ├─ testcases/conftest.py
       │    ├─ 读取运行时配置
       │    ├─ test 环境启动 MockApiServer
       │    ├─ 为每条业务测试创建独立 VariableContext
       │    ├─ 创建 ApiRunner
       │    ├─ core 用例显式登录
       │    └─ regression 用例显式登录并发布资源
       ├─ core.case_loader 严格加载 YAML
       ├─ core.ApiRunner
       │    ├─ 合并 base/case Header
       │    ├─ utils.DebugTalk 解析动态函数
       │    ├─ VariableContext 替换 ${variable}
       │    ├─ RequestClient 发送请求
       │    ├─ Extractor 写入当前上下文
       │    └─ Assertions 校验
       └─ 生成 JUnit XML；有 allure-pytest 时生成 Allure Results
```

## 目录边界

- `core/`：主执行链，缺少其中任一核心模块都会影响框架执行。
- `utils/`：日志、脱敏、DebugTalk、JsonPath、路径和 Allure 兼容等辅助能力。
- `testcases/demo/`：只验证框架的受控 Mock 演示用例。
- `tests/`：测试框架自身，防止后续重构破坏已验证行为。
