# Stage 7.1：YAML-first AI 失败分析接入说明

## 1. 定位

AI 是测试结束后的**失败解释器**，不是测试判定器。

```text
run.py → Pytest → AssertionEngine → 原始 PASS / FAIL
                               ↓
                       run.json + junit.xml
                               ↓
                       AI failure analysis
```

没有 AI、AI 超时或模型输出非法都不会改变原测试结论。

## 2. 输入与确定性事实

Stage 7.1 读取：

```text
reports/runs/<run_id>/run.json
reports/runs/<run_id>/junit.xml
```

Python 先生成不可由模型改写的 `F1/F2/...` Facts。AI hypothesis/next_check 必须引用真实 Fact ID。

## 3. 最终用户：直接使用 `config/ai.yaml`

`config/ai.yaml` 是真正主配置。完全不使用 Git 的用户可以直接填真实 Provider/Model/Key：

```yaml
ai:
  provider: my-provider
  timeout: 30

  providers:
    my-provider:
      protocol: openai_chat_completions
      base_url: https://provider.example/v1
      model: model-name
      api_key: real-user-key
```

这条路径不要求 GitHub、Jenkins、`.env` 或 OS 环境变量。

## 4. Git 开发者：可选 `config/ai.local.yaml`

公共/团队 Git 场景不希望真实 Key 进入仓库时，可以保留公共 `config/ai.yaml`，再创建：

```text
config/ai.local.yaml
```

例如只写：

```yaml
ai:
  providers:
    my-provider:
      api_key: real-local-key
```

该文件默认被 `.gitignore`。它是安全增强，不是最终用户必须使用的文件。

## 5. Home 主配置 fallback

Resolver 先找：

```text
<project>/config/ai.yaml
```

只有该文件不存在时才找：

```text
~/.ai-api-autotest-framework/ai.yaml
```

项目级 `config/ai.local.yaml` 仍可作为当前项目私有覆盖层。

## 6. 配置优先级

```text
CLI 临时覆盖
> config/ai.local.yaml
> 主 YAML（project ai.yaml；不存在才使用 Home ai.yaml）
> AI_* 环境变量 fallback
```

环境变量仅作为 CI Secret / 高级用户 fallback：

```text
AI_PROVIDER
AI_PROTOCOL
AI_API_BASE
AI_MODEL
AI_API_KEY
AI_TIMEOUT
```

## 7. CLI

完全离线：

```bash
python -m ai.cli analyze --run-dir reports/runs/<run_id> --no-ai
```

使用 YAML Provider：

```bash
python -m ai.cli analyze --run-dir reports/runs/<run_id>
```

临时覆盖：

```text
--provider
--protocol
--base-url
--model
--timeout
```

需要临时 Key：

```bash
python -m ai.cli analyze \
  --run-dir reports/runs/<run_id> \
  --api-key-prompt
```

框架**不提供 `--api-key VALUE`**，避免 Key 进入 shell history/process list。

## 8. Provider 与 Protocol 解耦

Provider 只是 YAML Profile 名；production Python 不按 DeepSeek/Qwen/OpenAI 厂商名分支。

```text
AIProviderConfig
→ protocol
→ AIClientFactory
→ Protocol Adapter
```

第一版协议：

```text
openai_chat_completions
```

因此同协议的新 Provider/模型只改 YAML。只有接入真正不同的 API 协议时才新增 Adapter。

## 9. 模型输出契约

`openai_chat_completions` Adapter 不会针对某个 Provider 修补字段或翻译枚举。所有 Provider
都必须遵守同一 Stage 7.1 输出 Schema，随后再交给 `validate_model_analysis()` 做确定性校验。

模型必须只返回一个 JSON Object：

```json
{
  "hypotheses": [
    {
      "title": "non-empty string",
      "confidence": "low",
      "evidence_refs": ["F1"],
      "reasoning_summary": "non-empty string"
    }
  ],
  "next_checks": [
    {
      "priority": 1,
      "action": "non-empty string",
      "evidence_refs": ["F1"]
    }
  ],
  "uncertainties": []
}
```

硬约束：

```text
confidence    -> 只能是 low / medium / high
priority      -> 正整数
evidence_refs -> 非空，而且只能引用本次 Evidence 中已有的 Fact ID
字段名/枚举值 -> 不翻译、不改写
输出           -> 严格 JSON，不包 Markdown fence
```

如果 Provider 返回合法 JSON 但不满足以上 Schema，框架会保留确定性 Evidence，并将
`ai_status` 降级为 `invalid_model_output`。框架不会把 `"高"`、`"High"`、`0.9` 等值
自动转换成 `high`，因为这会让不同 Provider 的行为逐渐侵蚀统一契约。

## 10. 输出 Artifact

```text
ai-analysis/evidence.json
ai-analysis/analysis.json
ai-analysis/analysis.md
```

`evidence.json` 是已脱敏确定性输入；`analysis.json` 包含 Facts、hypotheses、next_checks、uncertainties 和 ai_status；Markdown 只渲染经过 Validator 的结果。

## 11. 安全边界

- 结构化 password/token/cookie/API Key 脱敏；
- JUnit 自由文本二次 `sanitize_text()`；
- 文本先脱敏再截断；
- `AIProviderConfig.api_key` 不进入 dataclass repr；
- Provider 异常只保存 `error_type`，不保存 `str(exc)`；
- Key 不写分析 Artifact；
- `--api-key-prompt` 使用 getpass 隐藏输入。

## 12. 稳定降级状态

```text
success
unavailable
error
invalid_model_output
```

后三种仍保留确定性 Evidence，不改原 `run.json/junit.xml` 或 Pytest exit code。
