# Stage 6 CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 为 AI 辅助接口自动化测试框架增加可复用 GitHub Actions、参数化 Jenkins Pipeline 和报告归档能力，同时保持真实短链接系统只作为一个可选 SUT。

**Architecture:** GitHub Actions 负责云端框架/Mock CI，Jenkins 负责运行在可访问真实 SUT 的节点上。两者都只消费现有 `run.py`、依赖清单和报告目录，不复制业务执行逻辑。

**Tech Stack:** GitHub Actions、Jenkins Declarative Pipeline、Python 3.11、Pytest、JUnit XML、Allure Results。

## Global Constraints

- 公共 CI 配置不得写死短链接 URL、表名、Redis Key 或 `shortlink-local`。
- 业务测试必须通过 `python run.py --env ... --level ...` 执行。
- GitHub Actions 使用官方当前主版本 `actions/checkout@v6`、`actions/setup-python@v6`、`actions/upload-artifact@v7`。
- 新增 YAML 文件使用高密度中文注释。
- 报告归档必须在测试失败时仍执行。
- 计划书每次阶段变更同步更新。
